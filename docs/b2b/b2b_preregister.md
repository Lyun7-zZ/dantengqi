# B2b 预注册：H0+C vs H1+C

## 目的

在缓存都开启、其他条件相同的条件下，比较 routeWalls=3（H0+C）与 routeWalls=6（H1+C），选出后续研发基线；不是正式验收。

## 配置

- 两臂：`createGrandmasterPlusConfig({ routeWalls: 3|6, pathCache: true })`
- 3,000ms 硬预算 + 100ms 返回缓冲；固定宗师 3s
- 缓存：84 位身份核对，上限 200k，决策内清空
- 其余评估、计划、候选、排序、深度上限一致

## 样本

- 开局：id 95–114，共 20 个全新开局
- 每臂 40 局（20×双座位），共 80 局
- 种子：`97000 + openingId*2 + seat`
- 8 个 shard，双臂交错、独立进程
- 记录动作、终点、计时、深度、缓存统计、U 原因

## 选择规则（运行前冻结）

1. 任一臂出现非法/超时/缓存错值 → 暂停审计；
2. 某臂积分、胜率均不低，负率与 L+U 均不高，且至少一项改善 → 优先该臂；
3. 指标冲突或接近 → 优先低负率与 L+U，不牺牲胜率；无明确优势则保留 H1+C；
4. 不追加样本至显著，不选择性重跑。

## 禁止

- 不改固定宗师/地狱，不新增 UI，默认不启用缓存；
- 不实施增量路径、合法性短路、状态复制等第二变量；
- 不启动 M2/M3/M4，不合并 main。

完成后 HARD PAUSE。
