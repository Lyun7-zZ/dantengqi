# V2 架构设计（V2-0）

## 0. 前提修正

- 当前搜索是确定性 negamax/αβ，单一标量传播，不是概率期望模型；
- G-test 的同期对照是 G7+ 与 G9+，不能写成「H1+C 变成 13/5/16/6」；
- 失败口径按 L+U：共同风险 13、新增风险 4、共同败局 13；
- 只能说已测试版本未达 70/10，不能证明架构理论上限；
- 规则在越线时结算，不按任意节点静态距离差判胜/平；
- T0/E2-0 只否定了各自预注册机制，不等于排除所有战术或路径缺陷。

## 1. 目标与约束

- 3,000ms 整次决策 + 100ms 返回缓冲；
- 对固定 3s 宗师：胜率 ≥70%、负率 ≤10%、平局不限；
- U/非法/超时 = 0（正式验收）；
- 不改固定宗师/地狱，不新增 UI，不合并 main。

## 2. 共享决策骨架

```
State → CandidateSet → Search → RiskPolicy → EndgameSolver → DecisionExit
```

### 2.1 规则/状态层

- 直接复用 `src/rules.js`；
- 冻结字段：vWall/hWall/topWall、players、turn、firstPlayer、tolerance、drawMode、wallLimit、wallsUsed、plies、winner；
- 策略状态（计划、RNG、历史）单独编码，不混入规则状态；
- 缓存键必须覆盖墙图 + 行动方 + 墙资源 + 先手/容差。

### 2.2 候选层 E

- 生成：合法走子、即时终局动作、计划提议、关键攻守墙；
- 粗排：便宜特征（距离、出口、墙收益）；
- 展开：按预算选择性搜索；
- 记录：generated / legal / entered / completed / selected / source。

### 2.3 搜索层 A

- 以 anytime αβ 为首个可比较骨架；
- 已完成迭代与截断结果分开记录；
- 评分可能是 αβ 界，不当作精确值；
- 计划只作为「提议」，是否无条件裁决需单独实验。

### 2.4 风险层 C

- 优先使用可证明结果（胜/平/负）；
- 未证状态才使用经独立校准的风险估计；
- 无有效估计回退基线；
- 不把启发分数解释为概率，不把 U 改判平局。

### 2.5 定向求解 F

- 仅在可覆盖子空间触发；
- 全规则终局、严格证明、UNKNOWN 分开；
- 求解失败不得拖累正常决策；
- F0 审计结论：默认 wallLimit=Infinity，历史无墙耗尽状态，F1 不立项。

### 2.6 预算/返回层 B

- 单一全局时钟，100ms 返回缓冲；
- 日志与验证纳入外部 3s；
- 统一终局、安全平局、回退与来源记录；
- 所有返回动作必须合法。

## 3. 统一决策出口

所有路径（计划直返、搜索、越线、保护、截止回退）最终经过同一出口：

1. 动作合法性校验；
2. 立即终局判定（胜/平/负）；
3. 若已证胜/平，直接返回；
4. 否则按风险策略比较候选；
5. 无可信估计则返回基线动作；
6. 记录 source、耗时、深度、节点、是否截止。

## 4. 风险标签（C0 设计，不在本轮实现）

- 对代表状态，用固定宗师 + 多种子/参考搜索续局，得到 W/D/L/U 分布；
- 按 openingId 分组，训练/校准/测试隔离；
- 输出平滑概率与置信区间，不把单次续局当真值；
- 保护集：已证胜/平状态不得被降级；
- 参数在开发集冻结，不在测试集调参。
