# 蛋疼棋 · 联机服务器设计稿 v1.0

> 状态：**设计稿，尚未实现**
> 日期：2026-11-19
> 适用范围：回合制模式的联机（异步模式暂不接入）

---

## 1. 目标

把联机从「P2P + 公共信令」改成「一台服务器 + 客户端」，解决这些问题：

- 不需要 NAT 穿透，不需要 PeerJS，不需要手动粘贴连接码；
- 每一手由服务端校验，客户端改代码也无法作弊；
- 时钟以服务端为准，超时代走不会被某一方操纵；
- 断线重连是标准能力，而不是靠 P2P 运气；
- 为后续观战、房间列表、存档上云留出位置。

**不在本期范围**：账号体系、匹配、观战、房间列表、观战回放、跨版本兼容。

---

## 2. 已确定的决策

| 项 | 决定 |
|---|---|
| 权威性 | 服务端权威（服务端跑 `src/rules.js`） |
| 页面托管 | 与 WebSocket 同源、同端口 |
| 访问方式 | 公网 IP + `http://IP:6657`、`ws://IP:6657/ws`（无 HTTPS） |
| 旧联机 | 删除 PeerJS 与连接码路径 |
| 部署 | 一键安装脚本（自动识别 apt / dnf） |
| WebSocket 实现 | `ws` 库 |
| 一期范围 | 房间、对局、重连、计时、认输、悔棋、再来一局 |

## 3. 总体架构

```
┌──────────────┐        http://IP:6657          ┌─────────────────────────┐
│   浏览器 A   │ ─────────────────────────────► │  Node 进程（单端口）     │
│              │                                │  ├─ 静态文件服务          │
│  游戏页面    │        ws://IP:6657/ws         │  └─ WebSocket 升级        │
│  + ws 客户端 │ ◄────────────────────────────► │         │                │
└──────────────┘                                │         ▼                │
┌──────────────┐                                │  ┌───────────────┐       │
│   浏览器 B   │ ◄────────────────────────────► │  │ 房间表 + 对局  │       │
└──────────────┘                                │  │ rules.js 校验  │       │
                                                │  └───────────────┘       │
                                                └─────────────────────────┘
```

要点：

- **一个进程、一个端口**：`/` 返回页面，`/ws` 升级为 WebSocket。不需要反向代理。
- 服务端 `import` 仓库里的 `src/rules.js`、`src/path.js`、`src/board.js`——规则只有一份实现。
- 页面使用单文件构建产物（`dist/蛋疼棋.html`），部署时拷贝到服务端静态目录。

## 4. 协议设计

### 4.1 传输与编码

- WebSocket，文本帧，JSON；
- 每条消息必须含 `t`（类型）；对局消息含 `ply`；
- 单条消息上限 **16 KB**，超过直接断开；
- 服务端每 20 秒发一次 `ping`，客户端 10 秒内未回 `pong` 视为掉线。

### 4.2 版本

```js
PROTOCOL_VERSION = 2;      // 服务器版独立编号，与旧的 P2P 版不兼容
RULES_VERSION = "1.3";     // 沿用现有规则版本
```

握手不一致时返回 `error { code: "version-mismatch" }` 并关闭连接。

### 4.3 客户端 → 服务端

| `t` | 字段 | 说明 |
|---|---|---|
| `hello` | `version`, `rules`, `room?`, `token?` | 建连第一条；带 `room+token` 表示重连 |
| `create` | — | 创建房间，返回房间码与座位 |
| `join` | `room` | 加入房间 |
| `action` | `ply`, `action` | 提交一手（服务端校验） |
| `undo` | `op: "request" \| "accept" \| "decline"` | 悔棋 |
| `resign` | — | 认输 |
| `rematch` | `op: "request" \| "accept" \| "decline"` | 再来一局 |
| `pong` | — | 心跳回应 |

### 4.4 服务端 → 客户端

| `t` | 字段 | 说明 |
|---|---|---|
| `welcome` | `seat`, `token`, `room`, `rules` | 分配座位与重连令牌 |
| `room` | `room`, `seat`, `phase` | 房间状态变化（等待 / 开始 / 结束） |
| `dice` | `first`, `sides` | 服务端掷骰结果与先手、执边 |
| `state` | `state`, `clocks`, `plies`, `hash` | 完整局面（开局、重连时下发） |
| `event` | `ply`, `action`, `hash`, `by` | 单步广播 |
| `clock` | `seat`, `moveLeft`, `bank`, `inBank` | 每 500ms 同步一次剩余时间 |
| `undo` | `op`, `by` | 悔棋请求/结果 |
| `result` | `winner`, `reason` | 结束（`exit` / `resign` / `timeout` / `draw`） |
| `error` | `code`, `message` | 错误 |
| `ping` | — | 心跳 |

### 4.5 错误码

| code | 含义 |
|---|---|
| `version-mismatch` | 协议或规则版本不一致 |
| `room-not-found` | 房间码不存在 |
| `room-full` | 房间已满 |
| `not-your-turn` | 不是你的回合 |
| `illegal-action` | 规则校验失败（附带 `reason`） |
| `stale-ply` | 手数不匹配（重复/乱序提交） |
| `token-invalid` | 重连令牌无效 |
| `rate-limited` | 提交过于频繁 |

## 5. 房间与对局流程

### 5.1 状态机

```
        create
          │
     ┌────▼────┐   join    ┌─────────┐  双方就绪  ┌────────┐
     │ waiting │ ────────► │  ready  │ ─────────► │ playing│
     └────┬────┘           └─────────┘            └───┬────┘
          │ 房主离开/超时                              │ 结束
          ▼                                           ▼
       closed ◄────────────────────────────────── finished
                                                        │ rematch
                                                        ▼
                                                     ready/playing
```

- `waiting`：只有房主，等待对手；**10 分钟**无人加入则房间回收；
- `ready`：两人到齐，服务端掷骰、分边，下发放 `dice`；
- `playing`：逐手校验与广播；
- `finished`：保留 5 分钟供双方查看结果与再来一局，之后回收。

### 5.2 座位与房主

- 房主 = 先创建者，座位在创建时随机分配；
- 对手离开 → 房间立即关闭，通知剩余玩家；
- 房主离开 → 无论对局是否进行，房间关闭（一期不做主机迁移）。

### 5.3 掷骰

- 服务端 `Math.random` 掷两颗（或同一颗骰子各掷一次，直到不同）；
- 点数大者在「先手 / 选边」中二选一，另一项归对方；
- 结果通过 `dice` 广播，客户端不再自行掷骰。

> 注：服务端掷骰天然可信，不再需要 commit-reveal。

### 5.4 行动处理

```
收到 action { ply, action }
  ├─ ply !== 当前手数        → error stale-ply
  ├─ 不是该座位回合           → error not-your-turn
  ├─ validateAction 失败      → error illegal-action
  ├─ applyAction 成功
  │    ├─ 计算 stateHash
  │    ├─ 广播 event { ply, action, hash }
  │    ├─ 若 winner !== null → 广播 result，房间转 finished
  │    └─ 否则切回合、重置该侧计时
  └─ 记录到对局历史（内存）
```

### 5.5 悔棋

- 当前回合方可请求；对方 **30 秒**内确认，超时视为拒绝；
- 同意后服务端回滚一手（恢复墙、棋子、计时），广播 `undo {op:"done"}` 与新的 `state`；
- 每方 3 次上限，服务端计数。

### 5.6 认输 / 再来一局

- 认输立即结束，广播 `result { reason: "resign" }`；
- 再来一局需双方同意：一人 `request`，另一人 `accept` 后服务端重开（重新掷骰）。

---

## 6. 计时

- 服务端持有权威时钟：`perMove`（默认 30 秒）+ `bank`（默认 300 秒）；
- 每 **200ms** 推进一次当前回合方的计时；
- 归零 → 服务端用 `autoMove` 代走，广播 `event` 并附 `reason: "timeout"`；
- 每 500ms 广播一次 `clock`，客户端只负责显示，不参与判定；
- 客户端本地也可平滑插值显示，但以服务端 `clock` 为准。

---

## 7. 断线重连

1. 加入/创建成功时，服务端下发 `token`（32 字节随机，base64url）；
2. 客户端把 `{room, token}` 存进 `localStorage[danteng.reconnect]`；
3. 断线后自动重连（1s、2s、4s… 上限 10s），重连时 `hello { room, token }`；
4. 服务端校验 token → 恢复该座位 → 下发 `state` + `clock`；
5. **90 秒**内未重连：对局结束，判掉线方负（沿用现有规则），房间保留 5 分钟给出结果。

客户端断开但服务端仍在计时的部分，重连后用 `state` 覆盖本地，不做增量合并。

---

## 8. 数据与持久化

- 房间与对局**只存内存**，服务重启即丢失（一期接受）；
- 可选增强（本期不做）：每分钟把进行中房间写一份 JSON 快照到 `data/`，重启后恢复。

---

## 9. 安全与限制

| 项 | 值 |
|---|---|
| 单房间人数 | 2（一期不开放观战） |
| 单条消息 | ≤ 16 KB |
| 单连接速率 | 10 条/秒，超出返回 `rate-limited` |
| 单 IP 连接数 | ≤ 8 |
| 房间数上限 | 200（超过拒绝创建） |
| 输入校验 | 所有字段类型/范围校验，非法即断 |

明文传输（无 HTTPS）是已知取舍：适合朋友间使用，不适合公开推广。

## 10. 服务端代码结构

```
server/
  index.js       进程入口：http 静态 + ws 升级 + 优雅退出
  rooms.js       房间表、房间码生成、回收

  install.sh     一键安装脚本
```

## 12. 部署

### 12.1 一键脚本 `deploy/install.sh`

1. 检测包管理器（apt / dnf），安装 `curl`、`ca-certificates`；
2. 安装 Node 20（优先发行版包，版本过低则用 NodeSource 源）；
3. 创建 `/opt/danteng`，拷贝 `server/`、`src/`、`dist/蛋疼棋.html`；
4. `npm install --omit=dev`；
5. 写入 `/etc/systemd/system/danteng.service`（`Restart=always`、开机自启）；
6. `systemctl daemon-reload && enable --now danteng`；
7. 若检测到 `ufw`/`firewalld`，尝试放行 6657，失败则打印手动命令；
8. 输出访问地址与常用运维命令。

> 脚本必须**幂等**：重复执行只做升级，不重复创建服务。

### 12.2 运维

```bash
systemctl status danteng
journalctl -u danteng -f
systemctl restart danteng
```
